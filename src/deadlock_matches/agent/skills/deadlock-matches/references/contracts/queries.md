# Queries

Start ad-hoc polars from these helpers instead of rewriting boilerplate. For any count, rate, or total over your own matches, call `queries.summarize()` on a metric view. Do not join `players` to `matches` by hand, and do not write your own win rate. Drop to `scan()` only when the column you need is on none of the views.

```python
from deadlock_matches import queries

queries.summarize(
    queries.my_games, by="hero", measures=["games", "wins", "win_rate"]
).collect()
```

## The semantic layer

- `summarize(view, by=, measures=, filters=, **view_args)` lazily groups a metric view by its declared dimensions and aggregates its measures. `by` and `measures` take names the view declares, or a declared synonym that resolves back to the declared name. `filters` takes a value, a list of values, or a raw expression. Everything else passes through to the view factory (`accounts=`, `tz=`, plus `days=`, `since=`, and `hero=` on `record_games`). `parquet_dir=` is not a view parameter but picks which files get read, so `summarize` makes it ambient for the whole build. An unknown name raises with the valid names listed. Omit `by` for a single total row. Call `.collect()` at the presentation boundary. An all-mode table needs `match_mode=None, game_mode=None, ranked=None`, because Street Brawl shares Standard's match mode and the default also filters `ranked_type`.
- `registered_views()` and `describe_views(name)` list the views that `summarize` accepts, in code and as text. `deadlock schema --views` prints the same thing. The views cover match and account games, record games, damage and healing sources, hero damage detail, and soul sources. They also cover movement games, fight counters, compare-interval gains, cumulative marks, net-worth milestones, stack counters, and permanent buffs. Each declares its grain, parameters, dimensions, and measures.
- A rate goes through `try_divide(numerator, denominator)` over two aggregates, so `win_rate` is total wins over total scored games at whatever grain you asked for. It is never the mean of per-group rates. A measure may also be written from other measures, for example `lambda measure: try_divide(measure["wins"], measure["scored_games"])`, so one definition is not respelled twice.
- Measures hold raw values. A proportion is not multiplied by 100 and nothing is pre-rounded. Scale and format only where you print. Every measure declares a `unit` from `queries.UNITS`, and `measure.display_format` says how to print it. A `Format` carries `decimals`, a `scale` (100 for a proportion), `group` for thousands separators, a prefix or suffix, and `small`, which keeps the decimals that a whole-number column rounds away. `queries.view_measure(view, name)` looks one up, and `cli/render.py` prints whole tables through them, so no report scales or rounds a number by hand.
- `view_frame(view, columns=None, parquet_dir=None)` builds a view as a frame instead of aggregating it, with its dimensions materialized as columns. It is how you get rows out of a view: `view_frame(my_games(accounts, tz), parquet_dir=pq)`. Leave `columns` alone unless you want a join pruned. It names what you go on to read and does not project. Columns that a view picks up from a join are prefixed with the join alias, so match details on `my_games` are `matches.duration_s`, `matches.start_time`, `matches.not_scored`, and so on.
- `compare(view, [Scope("you", ...), Scope("them", ...)], by=, measures=)` is the sibling of `summarize` for a delta across two row sets, which a measure can never be, because the two sides live in different groups. A `Scope` carries the export it reads (`parquet_dir=`) alongside the view arguments, and it can take a ready `lf=` instead. It takes exactly two named scopes, and each name prefixes its side, so the columns come back `you_total`, `them_total`, and `gap_total`. The gap always reads the first scope minus the second, and every group key that either side has survives. A missing side stays null in its own column. Counts and sums declare `missing="zero"` for the gap, while rates, means, medians, extrema, and windowed measures keep the safe `"null"` default. Use it instead of a hand-rolled full join.
- `direction` on a measure says which way is good: `"maximize"`, `"minimize"`, or blank. It describes the measure, never the delta, so a `minimize` measure with a negative gap is the good news. `render.reading(measure, gap)` turns the pair into "better" or "worse", which the compare tables print after the gap. Do not print "ahead" or "behind", because those already mean a lane soul lead.
- `Window` on a measure covers what plain aggregation gets wrong. `semiadditive="last"` with an `order` and a `partition` collapses every series to its final sample before the measure aggregates, the only safe read of a running total. `stat_snapshots` uses it. Registration enforces all or nothing: on a view where one measure declares the collapse, every measure does. `range="cumulative"` turns the grouped result into a running total down the ordered dimension, which then has to be one of the `by` names. `record_games.cum_net` uses it, and its `order` names day, week, and month.

## Metric views

`deadlock schema --views [name]` prints the grain, arguments, dimensions, and measures of every view. The notes below say when to reach for a view and add what that printout cannot show.

- `my_games` is the default view for your own games. It holds one row per match and account, so two of your accounts in one lobby are two rows. Ranked play is the standing default. See [Ranked](../patterns/ranked.md).
- `record_games` is the winrate window at one row per match, so its `wins` counts matches where `my_games` counts account-games. `daily_record`, `abandon_record`, and `unscored_record` share one collected frame through `games=`.
- `stat_snapshots` is the `stats` table as a view, for a measure over time. `games` is an explicit match and account scope and is trusted as is. See [Stats snapshots](../patterns/stats.md).
- `damage_source_games` is the per-source view for one hero, with duplicate total rows and non-hero targets already removed. `stat=` also covers `healing` and `heal_prevented`. See [Damage tables](../patterns/damage.md) for the two rate families.
- `hero_damage_games` is the finest damage grain, for an answer per enemy or per bullet series. Leaving `accounts` out keeps every dealer, and it does not fall back to `config.toml`.
- `soul_source_games` is one row per nonzero final soul source. See [Soul sources](../patterns/soul-sources.md).
- `movement_games` is the per-game movement view. Its means weight every game equally and leave games without movement rows out.
- `combat_games` is the fight-counter view behind `deadlock compare combat`. A game with no tracked counters keeps zeros instead of dropping out, so the per-game rates divide by every game.
- `buff_games` is the permanent and bridge buff view. It has no time axis, so for timing use `buff_intervals` or the `buff_pickups` table, which only matches from build 6712 on fill. See [Custom stats](../patterns/custom-stats.md).
- `stack_games` is the final stack counters, with no timestamps. The trackers are Sticky Bomb, Trophy Collector, Glass Cannon, Restorative Locket, and the Guided Owl, Assassinate, and Combo kill counters.
- `compare_intervals` gives the per-interval gains that `deadlock compare` medians for both sides. It keeps full intervals only, takes kills and deaths from the `deaths` table, and forward-fills each source of a soul composite on its own clock.
- `cumulative_marks` gives the cumulative value at fixed marks and `milestone_games` the minute each net-worth target was first crossed. A game that ended before a mark contributes no row, so read `games` alongside the median.

## Frames

- `scan("damage")` lazy-reads a table by name.
- `player_rows()` lazy-reads `players` with the current hero display name derived from `hero_id`. Raw `scan("players")` intentionally has no `hero` column.
- `daily_record()` is the per-day W/L frame behind `deadlock winrate`.
- `abandon_record()` is one row per scored match in the same window where someone abandoned. `you`, `ally`, and `enemy` flag who left, and `returned` means the leaver reconnected. See [Matches and players](../patterns/matches-and-players.md) for the reconnect rule. Backs the winrate footer.
- `unscored_record()` lists the `not_scored` games that the winrate table leaves out, with the same window filters.
- `lane_records(days=, since=, hero=, mark_s=540)` is one row per scored match. `lane_net` is your side of the assigned lane minus the enemy side, as net worth at the last stats snapshot inside the mark. `my_early` is your deaths inside the window, `worst_early` the most deaths on a single teammate inside the window, and `ally_left` the abandon flag. Backs `deadlock laning`. A match without a lane snapshot drops out.
- `item_buys("Echo Shard")` lists your purchases with the `buy_n` order within the match. `item_buys(tier=4)` keeps one shop tier with `buy_n` unchanged. See [Item events](../patterns/item-events.md) for the tier rule.
- `item_games("Echo Shard", "Mirage", since="2026-06-30")` is one row per game. It carries the first buy time, the buy order (`buy_n`), the same-tier order (`tier_buy_n`), and the first same-tier purchase (`first_tier_item`, `first_tier_time_s`). It also carries `is_first_tier_item`, `owned_s`, the item damage, and `dealt_after_buy`, your hero damage while owning it and the denominator for `percent_of_hero_damage`. In the item's own buy and order columns, null means not built. A sold buy still counts as built. `since` caps to a patch window. `effective_cost` sums the era prices of its buys minus the components they consumed, and is null without the committed asset history. Backs `deadlock item`.
- `item_events_effective()` is `item_events_priced` plus `effective_cost`. See [Item events](../patterns/item-events.md).
- `hero_damage()` is the damage table pre-filtered to detail rows on hero targets with zero-value rows dropped, a safe base for any per-source sum. `stat=` picks healing, mitigated, and so on. It carries the current `source_name`, `category`, and `delivery` columns derived at read time. Parquet stores only the stable `source_class`.
- `hero_name()`, `damage_source_name()`, `imbued_ability_name()`, `accolade_name()`, `stack_name()`, and `stack_class_name()` are polars expressions that resolve current asset labels from stable ids and classes. `with_hero_name`, `with_damage_source_name`, and `with_stack_labels` add the conventional columns to a frame.
- `soul_source_name()`, `lane_name()`, `objective_name()`, `objective_lane()`, `buff_family()`, and `buff_level()` are the fixed-mapping labels, and they resolve from stored ids the same way. `with_soul_source_name`, `with_lane_name`, `with_objective_labels`, and `with_buff_labels` add the conventional columns.
- `damage_category()` and `with_delivery(frame)` are the read-time classifiers over `source_class`. See [Damage tables](../patterns/damage.md). `with_delivery` needs `matches` and the exported `item_history` in the parquet directory, nothing outside it.
- `damage_by_source("Mirage", accounts=, matches=)` gives whole-game totals per damage source across your games of a hero, one row per gun, ability, or item source with `games`, `total`, `per_min`, `per_min_owned`, `per_1k`, and `percent` of hero damage. It is the aggregate counterpart to the per-interval `deadlock match --damage`. `matches=` scopes to specific match ids. It is an eager frame and raises if you never played the hero. `stat="healing"` swaps the figure and `stat="heal_prevented"` the anti-heal table, both behind `deadlock healing`.
- `damage_game_records("Mirage", days=, since=)` is one row per game of a hero in oldest-first order. It carries the hero damage split by delivery (`total`, `gun`, `abilities`, `items`), the `_pct` shares, and day, won, and K/D/A. Backs `deadlock damage`, which feeds its match ids into `damage_by_source` so both tables cover the same games. The CLI caps only the printed per-game table at 10. Fuzzy hero names resolve, and it raises on an unknown hero or zero games.
- `healing_game_records("Mirage", days=, since=)` is the healing twin, with `total`, `abilities`, `items`, `self`, the matching `_pct` shares, and `prevented` (0 when none, no `_pct`). Backs `deadlock healing`.
- `souls_by_source("Mirage", accounts=, matches=)` is the souls mirror over `soul_sources`: whole-game souls per income source across your games of a hero. `games` counts the games where the source paid, because `soul_sources` holds a zero row for every source in every game. `souls` is the in-game souls plus orbs total. `secured_orbs`, `minutes` (the combined length of the games where the source paid, added 2026-07-15), `percent` of total, and `orb_share` complete it. Backs the `deadlock souls` source table.
- `souls_game_records("Mirage", days=, since=)` is the souls twin, one row per game with `total` (gross souls, orbs included) and the `waves`, `roaming`, `combat`, and `objectives` sums (`queries.SOUL_GROUP_COLUMNS`) plus the `_pct` shares. Catch-up and rare sources count only toward total. Backs `deadlock souls`.
- `combat_game_records("Mirage", days=, since=)` is the combat twin over `custom_stats` finals, one row per game. It carries `shots`, `hits`, and `headshots` against heroes only, and `parries` and `missed_parries`, where Counterspell auto-parries count as landed. `hit_pct` is hits over shots and `headshot_pct` is headshots over hits, the in-game convention. Both percents are null in a game with no tracked shots, and the counters fill 0. Backs `deadlock combat`. The report sums everything else (range bands, uptime counters) through `custom_stat_totals(accounts, matches)`, a per-group and per-stat total and per-game mean over the final snapshot values.
- `combat_hero_records(days=, since=)` is one row per hero with games and the summed aim and parry counters. `hit_pct` and `headshot_pct` are recomputed from the totals, so a high-volume game carries its proper weight.
- `custom_stats(stat=, group=, accounts=, matches=)` is the hidden counter table with hero, won, and local day joined, every filter optional. It returns final values by default, and `final=False` returns the cumulative snapshot rows. Interval diffs are valid for everything except the `Bullet Stats` percents. Backs `deadlock match --combat`.
- `aim_rates(hero=, accounts=, min_shots=100, min_games=50)` scores every archived player-game by aim against heroes, with `hit_percentile` and `headshot_percentile` ranked within the hero (99 is the top 1%). It is the cheat-spotting frame: join a suspicious game's enemies and read their percentiles. Simultaneous 97+ on both at high shot volume is the aim-assistance shape. Percentiles rank the full archive before the accounts filter, and go null until the archive holds `min_games` of the hero (`hero_games` carries the population). A thin local archive crowns a "100th percentile" trivially, so never present that as a cheat signal. It is an eager frame and takes about 0.03 s on the current archive.
- `final_stats()` is the last snapshot per match and player with hero and won joined and `accuracy` and `headshot_rate` computed.
- `team_damage_ranks()` ranks every player's final hero damage within their team per match. `top_team_damage` flags the damage chart top.
- `ability_upgrades()` lists the ability purchases and upgrades in spend order with the level and soul requirement for each purchase or the cumulative AP spend.
- `hero_scaling()` is the per-hero per-level reference frame (`base_health`, `spirit_power`, `required_souls`) with one row per patch era. `hero_scaling_asof(left)` as-of joins it by hero_id and level on `start_time`.
- `skill_rating(column)` maps a badge level column to the current labels with Roman subranks ("Emissary IV"). `skill_rating_asof(column, at="start_time")` resolves the labels per row through the committed rank history, so a pre-rename badge keeps the name its era used. The lobby and rating columns print through it.
- `my_deaths()` joins deaths to your games with hero, won, and day.
- `death_context(radius=2000)` adds allies, enemies, solo, and outnumbered at the death second. It raises unless movement is exported, so check `table_exists("movement")` first.
- `hero_games(hero, accounts=, since=)` lists your selected-mode games on one hero as a match_id and account_id frame, with ranked play as the default. It is your side of `deadlock compare`, and `since` is the patch-window cap.
- `game_rates(games, stat)` gives the whole-game rate per minute of one compare stat, one row per game, for the compare summary and Total rows.
- `cumulative_at(games, stat, marks_s)` gives the cumulative value at given game times per game, the last sample at or before the mark, only for games that reach it. Backs the `soul_sources` gap table.
- `cumulative_stat_target_times(games, targets, stat="souls")` gives the minute at which each game first crosses each target. The minute is interpolated between stats snapshots. Backs `--milestones`.
- `match_intervals(match_id, account_id, interval_s=300)` splits one player's match into per-interval gains diffed from the cumulative snapshots. The gains are souls, kills, deaths, assists, damage, damage_taken, obj_damage, healing, heal_prevented, creeps, neutrals, denies, and souls_min. Kills and deaths come from the deaths table because both snapshot counters drift. Backs `deadlock match`.
- `enemy_damage_intervals(match_id, account_id, interval_s=300, dealt=False)` gives one player's damage exchange per enemy hero as per-interval gains from `damage_targets`. The default is damage taken from each enemy, and `dealt=True` flips to damage dealt. It keeps hero dealers and targets only, forward-fills each source before the per-enemy sum, and orders enemies by match total. Backs the per-enemy tables in `deadlock match --deaths`, `--kills`, and `--damage`.
- `enemy_damage_totals(games, dealt=False)` is the whole-game twin, one row per enemy from the final-total `damage` table, so a plain sum is safe. Use it for totals, and use `enemy_damage_intervals` only for timelines.
- `soul_intervals(match_id, account_id, interval_s=300)` gives one player's souls as per-source interval gains from `soul_sources`. The value is souls plus souls_orbs, the sources with any souls are ordered by match total, and the forward-fill matches `damage_intervals`. Backs `deadlock match --souls`. The CLI maps `source_name` to the in-game screen labels and the Waves, Roaming, Combat, Objectives, Catch-Up, and Other groups.
- `damage_intervals(match_id, account_id, interval_s=300, stat="damage")` gives one player's damage to heroes as per-source interval gains from `damage_sources`, detail rows only, ordered by match total. Backs `deadlock match --damage`.
- `source_intervals(games, interval_s=300, stat="damage")` does the same across many matches at once. `games` is any frame with match_id and account_id columns, for example `my_games` or `tracked_player_games` rows. It adds a `full` flag for whole windows, and `stat="healing"` covers healing.
- `source_totals(games, stat="damage")` is the whole-game twin of `source_intervals`, one row per source from the final-total `damage` table. Use it for any totals-by-source number.
- `buff_intervals(match_id, account_id, interval_s=300)` counts one player's statue pickups per interval and buff family from `buff_pickups`, with `value` the summed recorded stat. The columns follow `queries.BUFF_INTERVAL_SCHEMA`: interval, start_s, end_s, buff, pickups, and value. Every family the player picked up gets every interval up to the match end, with 0 pickups in an empty cell. The last `end_s` clips to the match duration. `value` is null when any pickup in the cell lacks its stat. An empty frame means the match records no pickup times, which is every match before build 6712. Backs the timeline in `deadlock match --buffs`.
- `team_intervals(match_id, interval_s=300)` gives both teams' souls gained per interval with the running lead (team 0 minus team 1). Backs `deadlock match --teams`.
- `laning_stats(match_id, mark_s)` snapshots every player in one match at the last stats sample at or before `mark_s`. The columns are souls, damage, damage_taken, healing, heal_prevented, creeps, neutrals, denies, and `snap_s`, the sample used. Kills and deaths are counted from the deaths table inside the window, with hero, team, and lane joined. Backs `deadlock match --laning`.
- `movement_intervals(match_id, account_id, interval_s=300)` splits one player's movement into intervals. Each interval carries distance, the seconds alive, moving, stationary, sliding, in air, ziplining, and fighting, dash counts, and derived percents that are null while dead. It sums per-minute rows, so any interval that is a whole number of minutes is exact. Backs `deadlock match --movement`.
- `movement_scoreboard(match_id)` sums the same counts and percents per player for everyone in one match, with hero and team joined. Backs the lobby table of `deadlock match --movement`.
- `movement_profile()` gives per-match and per-player movement metrics (slide, dash, and air percents, distance, stationary percent, farm pace). Normalize per hero before comparing players. It reads `movement_intervals`, so it works with the default config.
- `movement_metrics()` gives the same metrics as a lazy frame without the farm and duration joins. Prefer it when farm pace is not needed.
- `movement_game_records(hero, accounts=, days=, since=, tz=)` is one row per game of a hero with day, result, K/D/A, and the movement metrics, null in a game without movement rows. Backs `deadlock movement`.
- `tracked_player_games(names, hero=, since=)` on `players` does the downloads to players to matches join. See [Tracked players](../patterns/tracked-players.md).
